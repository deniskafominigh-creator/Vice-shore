## 2. Паспорт проекта

| Параметр | Значение |
|---|---|
| Тип продукта | 3D-игра от третьего лица, короткая сюжетная песочница (2 миссии) |
| Стиль | полуреализм в духе GTA 6 / Vice City: солнце, море, вилла, сочные цвета, чистая геометрия без «пластикового» вида |
| Управляемый герой | один главный персонаж, вид от третьего лица |
| Место действия | вилла на скале/мысе; по сторонам — бесконечное море, вокруг — двор с баскетбольным кольцом |
| Платформа запуска | браузер (desktop-first), запуск одной кнопкой |
| Язык интерфейса и озвучки | русский |
| Технологический стек | Three.js + TypeScript + Vite (см. §4) |
| Объём | 10 задач, строго последовательно (§7) |
| Главный принцип | никаких заглушек; каждый шаг доводится до состояния «работает и можно улучшать» |

### Формулировка цели одним абзацем

Сделать законченную, аккуратно собранную 3D-сцену-игру: главное меню → загрузка → персонаж на вилле у бесконечного моря → первая миссия «покрасить стену в неокрашенной комнате» → вторая миссия «выйти во двор и забить два гола в баскетбольное кольцо», с корректной анимацией ходьбы, живой музыкой, озвучкой героя и чистой сценой без визуальных конфликтов объектов. Проект должен быть собран так, чтобы его можно было расширять новыми комнатами, миссиями и механиками без переписывания с нуля.

## 3. Видение и визуальный язык

### 3.1 Референс и его разбор

**Основной референс — два скриншота заказчика** (2026-11-24), полный разбор в `VISION.md`:
`docs/references/ref-outdoor.jpg` (внешняя сцена) и `docs/references/ref-painting.jpg` (покраска стены).

Коротко, что задаёт референс:
1. **Свет** — яркий солнечный **полдень**: солнце высоко, тени короткие и чёткие, небо насыщенно-синее с крупными кучевыми облаками. (Ранняя версия «золотой час» отменена как основная, остаётся только как опция цикла дня.)
2. **Цвет** — тропическая насыщенная палитра: бирюзовая вода, белый штакетник и белая обшивка дома с облупившейся краской, сочная зелень пальм и газона, серый гравий, маджента бугенвиллии как акцент. Не «серый реализм».
3. **Геометрия** — крупные чистые формы со скруглениями (chamfer/bevel), никаких голых кубов без фасок на переднем плане.
4. **Материалы** — PBR с потёртостями: выцветшая краска, дерево, гравий, штукатурка, ткань, кожа, стекло.
5. **Камера** — третье лицо чуть выше плеча, герой в нижней трети кадра, FOV 55–65°, с инерцией и мягкой «пружиной», не дёргается.
6. **Интерфейс** — минималистичный: плашка текущей задачи сверху, полоса прогресса слева-снизу, подсказки управления справа-снизу, полупрозрачные панели, скругления, локальный шрифт (без CDN).

**ЗАПРЕЩЕНО** в стиле: неоновый киберпанк, плоские ярко-кислотные цвета, «низкополигональная игрушечность», текстуры-заглушки в шашечку, отсутствие теней.

### 3.2 Тон и атмосфера
Спокойная курортная жизнь с лёгкой иронией: герой ремонтирует виллу, красит стену, играет в баскетбол. Озвучка — живая, разговорная, без пафоса.

## 4. Технические решения

### 4.1 Стек (зафиксировано)

| Слой | Решение | Причина |
|---|---|---|
| Язык | TypeScript, `strict: true` | ошибки ловятся на этапе сборки, а не в игре |
| Сборка | Vite | мгновенный dev-сервер, простой production-билд |
| 3D | three.js | достаточно для сцены такого масштаба, огромная экосистема |
| Анимация | `AnimationMixer` + `AnimationClip`, blend-tree, `SkinnedMesh` | штатный и предсказуемый путь |
| Физика | собственный лёгкий слой (кинематический персонаж, AABB/сферы, лучи); внешний движок (rapier/cannon) — только по решению, записанному в `DECISIONS.md` | не тащим тяжёлую зависимость на 2 миссии |
| Аудио | Web Audio API (`AudioContext`, `GainNode`, кроссфейды) | точный контроль над слоями и «ducking» |
| Интерфейс | HTML/CSS поверх canvas (DOM-оверлей) | быстрые, доступные меню и субтитры |
| Озвучка | заранее сгенерированные аудиофайлы в `public/assets/audio/voice/` + субтитры | детерминированно, работает офлайн |
| Состояние | собственный конечный автомат + `EventBus` | без «магии» фреймворков, легко читать и продолжать |

**ЗАПРЕЩЕНО:** внешние CDN (шрифты, скрипты, модели, звуки). Всё локально, проект работает полностью офлайн.

### 4.2 Требование «много типов файлов — одна общая кнопка»

Запуск проекта — **одна точка входа и одна кнопка**:

1. **Разработка:** `npm run dev` (или `start.bat` / `start.sh`, которые вызывают его) → открывается единственный `index.html`.
2. **Готовый билд:** `npm run build` → `dist/index.html` открывается двойным щелчком (все ассеты относительными путями, `base: './'`).
3. **Внутри игры:** та же одна кнопка — **«ИГРАТЬ»** в главном меню. Никаких вторых лаунчеров, никаких отдельных «вторых игр».
4. **Ассеты любого типа** (`.gltf/.glb`, `.ogg/.mp3`, `.json`, `.png/.webp`, `.vtt`) загружаются **только** через единый реестр — `src/core/Assets.ts` + манифест `src/data/assets.manifest.ts`. Прямых `new Audio('...')` или `GLTFLoader.load('...')` в игровых модулях быть не должно.

### 4.3 Единицы и координаты

- 1 единица three.js = **1 метр**.
- Ось **Y** — вверх, **−Z** — «вперёд» по умолчанию персонажа.
- Масштаб персонажа: рост **1.80 м**.
- Все размеры комнат/дверей/мебели — в метрах и правдоподобны: дверь ≥ 2.05 м высотой и ≥ 0.85 м шириной, проход между мебелью ≥ 1.0 м.

### 4.4 Бюджет производительности (обязателен)

| Метрика | Цель | Предел |
|---|---|---|
| FPS (desktop, средняя графика) | 60 | не ниже 45 |
| Draw calls в кадре | ≤ 200 | 300 |
| Треугольники в кадре | ≤ 500 000 | 800 000 |
| Размер текстуры | 1024 | 2048 |
| `devicePixelRatio` | clamp 1.5 | 2.0 |
| Время загрузки до меню | ≤ 5 с | 8 с |
| Аудио-CPU | ≤ 3 % | 5 % |

Любая задача, ухудшающая метрики за предел, не принимается.


## 5. Архитектурные принципы

1. **Единый игровой цикл.** Один `requestAnimationFrame`, фиксированный шаг физики (`1/60`), `delta` с ограничением сверху (не более 0.05 с) — чтобы игра не «телепортировала» персонажа после сворачивания вкладки.
2. **Конечный автомат состояний игры:** `BOOT → LOADING → MENU → PLAYING → PAUSED → CUTSCENE(опц.) → MENU`. Переходы только через `GameStateMachine.enter()`, каждое состояние имеет `enter/update/exit`. Никаких «флагов в глобальной области».
3. **Событийная шина.** Системы общаются событиями (`quest:completed`, `prop:interacted`, `player:footstep`), а не прямыми вызовами друг друга. Список событий — в одном файле `core/Events.ts`.
4. **Данные отделены от кода.** Квесты, реплики, расстановка мебели — в JSON/TS-данных (`src/data/`), код — универсальный «движок» для этих данных. Чтобы добавить третью миссию, не нужно править систему квестов.
5. **Всё, что можно проверить автоматически, проверяется автоматически.** См. `npm run audit:scene`, `npm run typecheck`, `npm run build`.
6. **Обратная совместимость по сохранению.** `SaveGame` имеет `version`; при росте версии — миграция, а не «сброс прогресса».
7. **Никаких «магических» значений в коде.** Константы геймплея — в `src/data/` или `src/core/Config.ts` с комментарием и единицей измерения.

## 6. Правила качества и запреты

### 6.1 Абсолютные запреты (нарушение = задача не сдана)

| № | Запрещено |
|---|---|
| 1 | Заглушки: пустые функции, `TODO` вместо логики, `console.log` вместо интерфейса, картинка-плейсхолдер вместо сцены, «временно» без записи в `PROGRESS.md` |
| 2 | Внешние CDN/ссылки на ассеты в сети |
| 3 | Резкие, линейные перемещения камеры/персонажа/меню без сглаживания |
| 4 | Наложение объектов (z-fighting, два меша в одном объёме, мебель в стене, предмет «врос» в другой) |
| 5 | Объект без коллизии, сквозь который проходит игрок; объект с коллизией, сквозь который он проходить должен |
| 6 | Изменение порядка задач, «перепрыгивание» задач, сдача задачи без критериев приёмки |
| 7 | Оставленный проект в нерабочем состоянии (не собирается / не запускается) |
| 8 | Переписывание `GOAL.md` без прямого указания владельца проекта |

### 6.2 Правила именования и кода

- Файлы модулей: `PascalCase.ts` (`PaintSystem.ts`); данные: `camelCase`/`kebab-case` (`quests.json`).
- Ассеты: `kebab-case` + префикс категории: `model-house-villa-01.glb`, `sfx-paint-loop-01.ogg`, `voice-m01-take-roller-01.mp3`, `music-menu-loop-01.ogg`.
- Каждый публичный класс/функция — короткий комментарий «что делает и зачем».
- Никаких `any` (кроме изолированных мест с комментарием), никаких неиспользуемых импортов.
- `npm run typecheck` и `npm run build` должны проходить **без ошибок и предупреждений**.

### 6.3 Правила стиля взаимодействия (общие)

- Ввод: **WASD** — движение, **Shift** — бег, **мышь** — камера, **E** — взаимодействие, **ЛКМ** — действие (красить/бросать), **Esc** — пауза/назад.
- Любое действие игрока получает **мгновенную визуальную или звуковую обратную связь** (не позже 100 мс).
- Подсказки в интерфейсе появляются в момент, когда действие доступно, и исчезают, когда недоступно.
- Все переходы между экранами — затемнение/сглаживание 0.3–0.6 с.

## 7. Порядок работ: 10 задач

**Задачи выполняются строго по порядку 1 → 10.** Следующая задача не начинается, пока предыдущая не принята по критериям. Порядок может быть уточнён только владельцем проекта.

### Задача 1. Главное меню

**Цель:** первое, что видит игрок, — живое, стильное, полностью рабочее меню, из которого запускается игра.

**Зависимости:** нет. Чтобы меню не было статичной картинкой, в этой задаче создаётся **минимальный слой мира**: небо, море, скала, терраса, солнце и дрейфующая камера (полноценный мир — задача 4).

**Что сделать:**
1. Экраны: `Загрузка` (прогресс загрузки ассетов, реальный, а не таймер) → `Главное меню` → `Настройки` → `Управление` → `Игра`.
2. 3D-фон меню: вид с террасы на море; камера медленно дрейфует по синусоиде (амплитуда мала, период 20–30 с), вода анимирована, солнце даёт блики. Ни в коем случае не статичная картинка.
3. Логотип: название + подзаголовок в стиле GTA (крупная типографика, локальный шрифт, лёгкое появление с прозрачностью и сдвигом).
4. Кнопки: **ИГРАТЬ**, **ПРОДОЛЖИТЬ** (активна при наличии сохранения), **НАСТРОЙКИ**, **УПРАВЛЕНИЕ**, **ВЫХОД**. Навигация мышью, клавишами `W/S/↑/↓` + `Enter`, `Esc` для возврата. Видимый фокус.
5. Настройки: общая громкость, музыка, эффекты, голос, качество графики (низкое/среднее/высокое), чувствительность мыши, субтитры вкл/выкл. Сохраняются в `localStorage`, применяются немедленно.
6. Переходы: затемнение 0.4 с, плавный вход в игру (камера заезжает за плечо героя), выход из игры в меню через `Esc` — без перезагрузки страницы и без потери состояния.

**Критерии приёмки:**
- Из меню можно войти в игру, из игры — вернуться в меню, и так 10 раз подряд без утечек и поломок.
- Меню полностью управляется клавиатурой; фокус всегда виден.
- Ни один переход не «режет» глаз: нет мгновенных переключений экранов.
- Настройки сохраняются после перезагрузки страницы.
- 60 FPS в меню на средней графике.

### Задача 2. Модель главного персонажа

**Цель:** один главный герой, полуреалистичный, с корректным скелетом и скиннингом, готовый к анимациям ходьбы (задача 6) и к предметам в руках (задача 7).

**Зависимости:** задача 1 (есть сцена и камера для осмотра).

**Что сделать:**
1. Решить и записать в `DECISIONS.md` источник модели: **(а)** процедурная сборка из кода (капсулы/скруглённые формы + параметрическая одежда) или **(б)** локальный `.glb` с ручным ригом. Рекомендация: **процедурная сборка + скелет в коде**, чтобы проект не зависел от внешних ассетов и оставался полностью «свой»; одежда — отдельными мешами для переодевания.
2. Пропорции: рост 1.80 м, голова ≈ 1/7.5 роста, плечи ≈ 0.45 м, кисти с пальцами (минимум по 3 фаланги на большой палец и 2 на остальные), ступни с носком и пяткой.
3. Скелет ≤ 60 костей: таз, позвоночник (3), шея, голова, челюсть (опц.), ключицы, плечи, предплечья, кисти, бёдра, голени, стопы, пальцы. Кости названы по схеме (`hips`, `spine_01`, `upperarm_l`…).
4. Скиннинг: контрольные точки — локоть, колено, пах, плечо, шея. **Не допускается** разрывов сетки, «схлопывания» и «резинового» изгиба при сгибе на 90°.
5. Материалы: кожа (шероховатость 0.45–0.6, лёгкий subsurface-эффект через emissive/френель), ткань футболки (нормали + тканевый рисунок), джинсы, кроссовки (резина/текстиль), волосы (плоские карты с прозрачностью). Все текстуры — атлас, ≤ 2048.
6. Лицо: глаза с бликом (не «мёртвые»), брови, рот; читаемая мимика не требуется, но лицо не должно быть маской.
7. Отладочный режим осмотра (`F3`): вращение модели, сетка скелета, вес влияния костей — чтобы можно было проверить качество скиннинга.
8. Модель ≤ 25 000 треугольников, ≤ 3 материала.

**Критерии приёмки:**
- Персонаж виден в игре в полный рост, корректно освещён, стоит на земле (не парит и не проваливается).
- При повороте камеры не видно разрывов сетки, «дыр», перевёрнутых нормалей.
- Тестовая поза «руки вверх», «присед», «поворот головы на 60°» не ломает модель.
- Отладочный режим показывает скелет и позволяет это проверить.

### Задача 3. Фоновая музыка, подходящая по ситуации

**Цель:** живая адаптивная звуковая дорожка, которая меняется по состоянию игры и никогда не «рвётся».

**Зависимости:** задача 1 (состояния игры).

**Что сделать:**
1. Слои: `menu` (спокойный чиллвейв/синты, 80–90 BPM), `explore` (ambient + мягкий бас + лёгкая перкуссия, 90–100 BPM), `mission` (тот же материал, но с драйвом — добавляются слои), `stinger_success`, `stinger_fail`, `stinger_quest`.
2. Реализация: Web Audio; каждый трек — зацикленный буфер с **точно выставленными loop-точками** (без щелчков на стыке). Кроссфейд 1.5–2.5 с между состояниями. Смена трека — по событию конечного автомата, а не «по таймеру».
3. Микс: громкость музыки по настройкам; при реплике героя музыка **приглушается** (−9 дБ) и плавно возвращается; при потере фокуса вкладки — пауза; при возврате — плавный вход.
4. Ambient-слой: море (петля прибоя), ветер, редкие птицы — с привязкой к зоне (у моря громче, в доме тише).
5. Никаких «чужих» треков из сети: либо собственная генерация аудио, либо локальные файлы с лицензией, записанной в `ASSETS.md`.

**Критерии приёмки:**
- Ни одного щелчка, обрыва или «двойного» наложения треков при 30 переходах меню↔игра↔миссия.
- Смена настроения слышна и соответствует ситуации (меню / прогулка / миссия).
- Голос всегда разборчив на фоне музыки; ducking работает.
- Ползунки громкости влияют мгновенно и раздельно (музыка/эффекты/голос).

### Задача 4. Дом, декор рядом, стиль GTA 6, вокруг — бесконечное море

**Цель:** цельная, красивая внешняя сцена: вилла на скале, двор с баскетбольной площадкой, пальмы и декор, вокруг — море без видимых краёв.

**Зависимости:** задачи 1–3 (мир, персонаж, звук), задача 5 идёт после и опирается на планировку дома.

**Что сделать:**
1. **Остров/мыс:** скала с уступом, лестница к воде (опц.), газон, дорожка к дому. Формы — со скруглениями и вариациями, а не примитивы.
2. **Вила (экстерьер):** белый бетон + тёплый камень + дерево + стекло, крупные террасы, навесы с ровными тенями, панорамные окна, бассейн (опц., рекомендовано), гараж. Крыша — не «плоский куб».
3. **Двор:** баскетбольная площадка с разметкой (для задачи 8) — щит, кольцо, сетка, стойка; шезлонги, зонт, растения в кадках, светильники. Всё стоит на земле и друг друга не пересекает.
   **По референсу обязательно:** белый деревянный **штакетник** по периметру (планки с острым верхом, две перекладины, облупившаяся краска), **гравийная дорожка** с бордюром от калитки к дому, газон, бугенвиллия (акцентный цвет), агавы/юкки, крыльцо с перилами у дома.
4. **Море:** большая плоскость с шейдером волн (сумма 3–4 волн Герстнера), нормали/блики, пена у камней, подводный цвет у берега. Горизонт — без видимого края: `fog` + скайбокс + бесконечная вода, камера никогда не должна видеть границу мира.
5. **Небо и свет:** скайбокс с солнцем **и кучевыми облаками** (референс `VISION.md §1`); по умолчанию — **яркий полдень**, не «золотой час». Направленный свет с тенями (каскад/одна зона — по бюджету), ambient/hemisphere, лёгкий bloom. Цикл дня — опционально, но если делается, то плавный (сутки ≥ 20 минут).
6. **Пальмы и растительность:** 3–4 варианта, разные повороты/масштабы, ветер через вершинный шейдер, LOD. Дальний берег с силуэтом деревьев на горизонте (референс `VISION.md §1`).
7. **Оптимизация:** instancing для повторяющихся объектов, `frustumCulled`, LOD, атласы.

**Критерии приёмки:**
- Обход всей внешней территории: камера нигде не видит край воды, «пустоту» или «шов» мира.
- Ни одного объекта, висящего в воздухе, утопленного в землю или пересекающего другой.
- Тени корректны и не «мерцают» (нет shadow acne/peter-panning).
- 60 FPS при полном обзоре сцены; draw calls в бюджете (§4.4).
- Стиль узнаваем как «солнечный курорт в духе GTA», а не «тестовая сцена».

### Задача 5. Интерьер дома: корректная расстановка

**Цель:** правдоподобный, проходимый интерьер, где каждый предмет стоит там, где должен, и ни с чем не конфликтует.

**Зависимости:** задача 4 (корпус дома).

**Что сделать:**
1. **Планировка:** прихожая, гостиная-столовая, кухня, спальня, ванная, **неокрашенная комната** (для задачи 1-й миссии), коридор к выходу во двор. Площадь — правдоподобная, потолки 2.8–3.2 м. Дверные проёмы ≥ 2.05 × 0.85 м, двери открываются наружу/внутрь без блокировки прохода.
2. **Расстановка по правилам:**
   - мебель стоит на полу (`y` = половина высоты от пола, с учётом ножек), не парит и не утоплена;
   - зазор между любыми двумя объектами ≥ 0.05 м; проход ≥ 1.0 м;
   - предметы не пересекают стены, окна, дверные полотна, светильники не врезаются в потолок;
   - ковры/декали — строго с `polygonOffset` и смещением 0.002 м, чтобы не было z-fighting;
   - всё, что должно быть интерактивным (валик, краска — задача 7), лежит на доступной высоте (0.8–1.3 м) и в зоне видимости.
3. **Освещение:** смесь направленного (из окон) + локальных источников; в неокрашенной комнате — рабочая лампа/окно, чтобы стена читалась.
4. **Материалы:** штукатурка, дерево, камень, металл, ткань, стекло. Неокрашенная стена — отдельный материал с поддержкой маски покраски (задача 7).
5. **Коллизии:** каждый предмет ≥ 0.3 м имеет коллайдер; мелкие — объединяются в один коллайдер-группу. Игрок не проходит сквозь мебель и не застревает в углах.
6. **Данные:** расстановка хранится в `src/data/props.ts` (id, модель, позиция, поворот, масштаб, коллайдер), а не разбросана по коду.

**Критерии приёмки:**
- Игрок проходит из прихожей в каждую комнату и во двор, нигде не застревая (проверка обходом всех маршрутов).
- Автоматический аудит (`npm run audit:scene`) не находит пересечений AABB в интерьере.
- Ни одного случая z-fighting при обходе комнат (визуальная проверка + отчёт аудита).
- Интерьер выглядит обжитым и логичным: мебель у стен, а не в центре прохода; на кухне — кухня, в спальне — кровать.

### Задача 6. Правильная ходьба с анимацией (плавно, без резкости и линейности)

**Цель:** персонаж ходит и бегает естественно, с инерцией, без «скольжения» и рывков.

**Зависимости:** задачи 2 (модель/скелет), 5 (интерьер для проверки), 4 (двор).

**Что сделать:**
1. **Ввод:** WASD/стрелки, мышь с pointer lock, `Shift` — бег, геймпад — опционально. Камера от третьего лица с пружинным сглаживанием (критическое затухание), без «дрожи» у стен; при столкновении камеры со стеной — плавное приближение (не рывок).
2. **Модель движения:**
   - ускорение ≈ 8 м/с², торможение ≈ 12 м/с², разворот — с ограниченной угловой скоростью (≥ 0.15 с на 180°);
   - скорости: шаг 1.6 м/с, бег 4.2 м/с; переход «шаг→бег» — плавный, по нарастанию ввода/времени нажатия;
   - **нельзя** мгновенно менять скорость и направление: движение всегда с инерцией (кривые ease-out, а не линейные).
3. **Анимации:** `idle`, `walk`, `run`, `start`, `stop`, `turn_left/right` (опц.), `pickup`, `paint_loop`, `throw`. Blend-tree по скорости (1D), `CrossFade` 0.2–0.3 с, `idle` — с дыханием и микродвижениями.
4. **Синхронизация шагов:** частота анимации пропорциональна реальной скорости (никакого «скольжения стоп» > 5 %); события `player:footstep` возникают в момент касания стопы (левый/правый) и запускают звук шага, соответствующий поверхности (плитка/газон/дерево).
5. **Согласование с землёй:** ступени и пандусы — через «прилипание» к поверхности (ground snap), а не «прыжки» высоты; при спуске/подъёме по лестнице персонаж не проваливается и не взлетает.
6. **Столкновения:** капсула персонажа, скольжение вдоль стен (не остановка «в лоб»), `step offset` ≈ 0.35 м, не «залезание» на мебель выше 0.35 м.
7. Отладочный экран (`F4`): скорость, состояние анимации, вес блендов, контакт стоп.

**Критерии приёмки:**
- Плавный старт и плавная остановка: визуально нет мгновенных включений/выключений анимации.
- Движение по диагонали, зигзагом, вокруг предметов — без «залипаний» и проскальзываний сквозь стены.
- Скольжение стоп не более 5 % (проверка по отладочному экрану: скорость анимации ↔ реальная скорость).
- Шаги озвучены и совпадают с касанием стоп.
- В помещении и во дворе поведение одинаково корректное; на лестнице — без провалов.

### Задача 7. Первая миссия: взять валик и краску, покрасить стену в неокрашенной комнате

**Цель:** первая полноценная игровая цепочка от подсказки до завершения, с сохранением прогресса.

**Зависимости:** задачи 5 (комната, стена), 6 (движение, взаимодействие), 3 (звук).

**Что сделать:**
1. **Данные квеста** в `src/data/quests.json`: `id: "mission_01"`, шаги: `take_roller` → `take_paint` → `paint_wall` (прогресс 0–100 %) → `complete`. Каждый шаг имеет текст подсказки.
2. **Предметы:** валик (на столе/стеллаже) и банка краски (на полу у стены). Подсветка при наведении (лёгкий контур/подсветка), подсказка «E — взять». Взятый предмет крепится к кости руки (`hand_r`), анимация взятия 0.4–0.6 с.
3. **Покраска (механика уточнена по референсу, `VISION.md §2`):**
   - стена делится на **вертикальные полосы** (~10), покрытие растёт **от движения валика вверх-вниз**, полоса проявляется постепенно;
   - управление: **W/S — вести валик**, **A/D — шаг к соседней полосе**, **R — макнуть валик в банку**, **E — отойти от стены**; удержание **ЛКМ** — альтернативный ввод для мыши;
   - у валика есть **запас краски** (расходуется от движения), банка стоит у стены — без макания краска кончается;
   - игрок с валиком у стены, raycast в плоскость стены → прогресс;
   - покрытие реализуется **маской** (render target / текстурная маска UV), а не «переключением текстуры»: пятно растёт непрерывно, не выходит за границы стены и не залезает на соседние поверхности;
   - расход краски: 100 % банки хватает ровно на стену + 15 % запаса (чтобы нельзя было застрять, но и не «бесконечно»); если краска кончилась раньше 100 % — подсказка вернуться к банке (второй этап банки — опционально);
   - обратная связь: звук валика (петля, привязанная к движению), брызги/частицы, изменение шероховатости (мокрая краска темнее, постепенно сохнет — плавно).
4. **Завершение:** 100 % покрытия → звук успеха, джингл, HUD «Стена покрашена», квест закрывается, **сохраняется в `SaveGame`**, разблокируется задача 8, реплика героя (задача 9). Завершение **невозможно** без валика и без краски.
5. **HUD миссии (по референсу):** плашка задачи сверху по центру, полоса «КОМНАТА» с процентом слева-снизу и подписью состояния («краска на валике»), подсказки управления справа-снизу.
6. **Надёжность:** повторный вход в комнату, перезагрузка страницы и «Продолжить» восстанавливают корректное состояние (покрашено/не покрашено), повторное выполнение не ломает квест и не дублирует награды.

**Критерии приёмки:**
- Цепочка проходится за 1–3 минуты без подсказок извне и без «застреваний».
- Покрасить стену невозможно без валика/краски; покраска не выходит за границы стены; прогресс не «прыгает».
- После перезагрузки состояние сохраняется.
- Задача 8 не активна до завершения задачи 7 и появляется сразу после.
- Ни одного визуального артефакта: пятно не z-fighting с стеной, валик не проваливается в руку/стену.

### Задача 8. Вторая миссия (появляется после первой): выйти во двор, забить два гола

**Цель:** вторая механика — физика мяча и баскетбольное кольцо с честным подсчётом голов.

**Зависимости:** задача 7 (условие появления), задача 4 (площадка).

**Что сделать:**
1. **Появление:** сразу после завершения миссии 01 — реплика героя + подсказка в HUD «Выйди во двор и забей два гола». Квест `mission_02` активен, кольцо и мяч подсвечены/обозначены.
2. **Мяч:** сфера r = 0.12 м, масса 0.6 кг; физика: гравитация 9.81, отскок ( restitution 0.65 ), трение качения, затухание вращения, отскок от щита/кольца/пола/стен, честное столкновение с персонажем. Вращение модели мяча соответствует скорости.
3. **Бросок:** удержание **ЛКМ** — заряд силы (0 → 1 за 0.9 с, индикатор), отпускание — бросок по дуге в направлении камеры/прицела. Бросок возможен только с мячом в руках; после броска — анимация, затем мяч можно подобрать (`E`).
4. **Подсчёт гола:** триггер-объём под кольцом **+** проверка, что мяч прошёл сверху вниз и целиком оказался внутри (никаких «голов» при отскоке от щита снизу или при пролёте рядом). Гол: звук, анимация сетки, частицы, HUD-счётчик `Голы: 1 / 2`.
5. **Завершение:** 2 гола → звук победы, HUD «Миссия выполнена», квест закрыт и сохранён, реплика героя. Промахи не отнимают голы. Счётчик устойчив к перезагрузке.
6. **Надёжность:** мяч не проваливается сквозь пол/кольцо/щит, не «залипает» в углах; при вылете за пределы площадки — возврат на исходную точку через 5 с (плавно, с подсветкой).

**Критерии приёмки:**
- Два гола засчитываются корректно; ложных засчитываний нет при 20 тестовых бросках мимо.
- Бросок ощущается управляемым (опытный игрок забивает ≈ с 2–3 попытки).
- Счётчик и статус квеста сохраняются после перезагрузки.
- Мяч никогда не «улетает» в бесконечность и не проходит сквозь геометрию.

### Задача 10. Убрать все конфликтующие предметы (эффект наложения)

**Цель:** финальная «уборка» сцены: ни одного визуального и физического конфликта объектов. Это задача-аудит, а не «полировка на глаз».

**Зависимости:** задачи 1–9 (вся сцена собрана).

**Что сделать:**
1. **Автоматический аудит** — `npm run audit:scene` (модуль `systems/CollisionAudit.ts`), отчёт в `docs/AUDIT_SCENE.md`. Проверки:
   - пересечение **AABB** любых двух объектов сцены (с порогом, игнорирование «мягких» пересечений: ковёр под мебелью — допустимо, но фиксируется как исключение);
   - **копланарные/близкие параллельные поверхности** (z-fighting): дистанция < 0.003 м на параллельных плоскостях;
   - объекты, висящие в воздухе (нет опоры под ними) и утопленные в пол/стену;
   - объекты без коллизии, сквозь которые проходит игрок, и коллизии без объекта;
   - объекты вне зоны сцены/навмеша, дубликаты (одинаковые id/позиции), объекты за пределами видимости;
   - «проваливание» персонажа: тестовые прогоны по маршрутам с логом застреваний.
2. **Исправление:** все найденные конфликты устраняются (перенос, изменение масштаба, замена модели, объединение коллайдеров, `polygonOffset`/`renderOrder`/`depthBias` для декалей).
3. **Исключения** допускаются только осознанно и записываются в `DECISIONS.md` с причиной («ковёр под диваном — визуально оправдано»).
4. **Регресс-защита:** аудит входит в обязательный чек-лист любой будущей задачи; после задачи 10 отчёт должен быть пустым (кроме зафиксированных исключений).
5. **Визуальная проверка:** прогон-облёт камерой по 20+ точкам сцены со скриншотами в `docs/audit-shots/` (или лог-отчёт) — глазами подтвердить отсутствие мерцаний.

**Критерии приёмки:**
- `npm run audit:scene` — 0 конфликтов, кроме исключений, явно записанных в `DECISIONS.md`.
- При обходе всех комнат и двора нет мерцающих поверхностей (z-fighting) и «мигающих» теней.
- Персонаж не застревает и не проходит сквозь объекты; мяч не проваливается сквозь геометрию.
- Метрики производительности не ухудшились (§4.4).

## 8. Definition of Done — общий чек-лист любой задачи

Задача считается выполненной только если **все** пункты отмечены:

- [ ] Все критерии приёмки задачи (§7) выполнены и **проверены вручную в игре**.
- [ ] `npm run typecheck` — 0 ошибок; `npm run build` — успешно; игра запускается из `dist/index.html`.
- [ ] `npm run audit:scene` — без новых конфликтов.
- [ ] Нет заглушек, `TODO`, «временных» решений и отладочного мусора в интерфейсе.
- [ ] Производительность в бюджете (§4.4).
- [ ] Работает после перезагрузки страницы и после `Esc → Продолжить`.
- [ ] Нет ни одного визуального «резака»: все переходы плавные.
- [ ] `PROGRESS.md` обновлён; новые решения — в `DECISIONS.md`; новые ассеты — в `ASSETS.md`.
- [ ] Проект оставлен в рабочем состоянии (следующий агент может продолжить сразу).

## 9. Чек-лист приёмки «глазами игрока» (прогон 10 минут)

1. Открыть игру одной кнопкой → меню появляется плавно, музыка звучит, ничего не мигает.
2. `Управление` и `Настройки` открываются и закрываются без задержек; настройки сохраняются.
3. `ИГРАТЬ` → загрузка → герой на вилле; камера плавно встаёт за плечо.
4. Пройти по дому: двери проходимы, мебель не мешает, нигде не застреваешь, стены не мерцают.
5. Выглянуть в окно/выйти во двор: море до горизонта, без края и швов; тени корректны.
6. Взять валик и краску, покрасить стену до 100 % — есть звук, джингл, подсказка, прогресс сохранён.
7. Выйти во двор, забить два гола — счётчик растёт честно, мяч ведёт себя как мяч.
8. Реплики героя звучат к месту, музыка приглушается, субтитры синхронны.
9. `Esc` → пауза → меню → `ПРОДОЛЖИТЬ` → всё состояние на месте.
10. 10 минут игры: 60 FPS, ни одной ошибки в консоли.

## 10. Протокол работы ИИ-агента (обязателен к исполнению)

1. **Прочитать** `docs/GOAL.md` целиком, затем `docs/PROGRESS.md` и `docs/DECISIONS.md`.
2. **Взять первую незавершённую задачу** из §7. Не перескакивать, не объединять задачи, не менять порядок.
3. **Спланировать** шаг: записать в `PROGRESS.md` короткий план (3–8 пунктов) до начала кодирования. Подумать, а не «сразу писать».
4. **Реализовать** маленькими проверяемыми кусками. После каждого куска игра должна запускаться.
5. **Самопроверка** по критериям приёмки, `typecheck`, `build`, `audit:scene`, ручной прогон §9.
6. **Обновить документацию:** `PROGRESS.md` (сделано / проверено / осталось / риски), `DECISIONS.md` (любое архитектурное решение + причина), `ASSETS.md` (новые файлы и лицензии).
7. **Отчитаться** строго в формате:
   - **Сделано:** …
   - **Проверено (как именно):** …
   - **Не сделано / перенесено (и почему):** …
   - **Риски и что улучшить дальше:** …
8. **Никогда** не оставлять проект нерабочим и не удалять чужие наработки без записи в `DECISIONS.md`.

## 12. Глоссарий

- **Квест/миссия** — запись в `quests.json` с шагами и условиями завершения.
- **Шина событий** — единый механизм сообщений между системами (`EventBus`).
- **Blend-tree** — плавное смешивание анимаций по параметру (скорость/направление).
- **Ducking** — автоматическое приглушение музыки под голос.
- **Аудит сцены** — автоматическая проверка пересечений, z-fighting, «висящих» объектов.
- **Одна кнопка** — единая точка входа (`index.html` / `npm run dev` / `start.bat`) и кнопка **ИГРАТЬ** в меню.
- **Заглушка** — временная имитация вместо работающей системы; в этом проекте запрещена.
