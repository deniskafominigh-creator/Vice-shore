## Задача 2 — Модель главного персонажа

**Статус:** готово к приёмке
**Дата:** 2026-11-24

### Что сделано
Процедурная модель **без внешних файлов**: скелет, геометрия и текстуры собираются кодом.

- `src/entities/character/CharacterProfile.ts` — пропорции (рост 1.80 м, голова 1/7.5, плечи 0.45 м) и **45 костей** (≤ 60): таз, 3 позвонка, шея, голова, ключицы, плечи, предплечья, кисти, **пальцы (большой — 3 фаланги, остальные по 2)**, бёдра, голени, стопы, носки. Правая сторона зеркалится автоматически.
- `src/entities/character/CharacterRig.ts` — сборка иерархии `THREE.Bone` + `THREE.Skeleton`, индекс костей для весов.
- `src/entities/character/GeometryKit.ts` — строитель «труб» с плавными весами, деформированные сферы, жёсткая привязка деталей, слияние геометрии.
- `src/entities/character/CharacterAtlas.ts` — атлас 1024² (кожа / футболка / джинсы / подошва / верх кроссовка / волосы), карта нормалей из карты высот, карта шероховатости.
- `src/entities/character/Character.ts` — сборка тела, одежды, кроссовок, лица и волос; позы, дыхание, отладочный режим.

**Скиннинг:** конечности и торс — непрерывные трубы, на суставах (локоть, колено, плечо, пах, шея) веса плавно распределены между костями → при сгибе нет разрывов и «резины». Проверено позами:
- `1` Покой, `2` Руки вверх, `3` Присед, `4` Поворот головы (60°+).

**Бюджет:** 8 936 треугольников (лимит 25 000), **2 материала** (тело-атлас + глянцевые глаза), скиннированный меш + детали головы на кости `head`.

**Встроено в игру:** герой стоит на террасе (в полный рост, с тенью), дышит и покачивается. Управление персонажем — задача 6, пока это «актёр» в кадре.

**Отладочный осмотр (F3):** камера плавно переезжает к модели, модель вращается, видны кости (SkeletonHelper поверх меша), `F5` — каркас, колесо мыши — приближение (у лица цель камеры поднимается), `1–4` — позы, `F3` — выход.

### Найденные и исправленные баги
1. **Инвертированная обмотка треугольников** в трубах (нормали смотрели внутрь) → обход исправлен + кольца автоматически разворачиваются, если деталь описана сверху вниз.
2. **Правая сторона без пальцев**: зеркалирование не учитывало имена вида `thumb_l_01`.
3. **mergeGeometries падал**: `RoundedBoxGeometry` неиндексированная, `SphereGeometry` индексированная → общая нормализация перед склейкой.
4. **Лицо уезжало к ногам**: группа деталей головы добавлялась и к кости, и к корню персонажа.
5. **Волосы закрывали лицо** («шлем») → шапка заканчивается выше бровей + отдельная масса на затылке.
6. **Тёмная «щель» в паху**: сквозь незакрытый объём таза просвечивала внутренняя сторона → таз сведён на конус, верх штанин закрыт.
7. **SkeletonHelper не рисовался**: helper нельзя класть внутрь группы персонажа (двойной трансформ) → добавлен в сцену.
8. **F3 ставил игру на паузу** (отпускание мыши считалось уходом из игры) → осмотр исключён из этого правила.

### Осталось / известные ограничения
1. Лицо и кисти — **стилизованные** (полуреализм «на минималках»): глаза-сферы с вершинными цветами, пальцы упрощённые. Для фотореализма нужен отдельный проход по голове (морщины, веки, уши-раковины).
2. Одежда — оболочка-смещение от тела: складок и швов нет, только тканевый рисунок и нормали.
3. Анимаций ходьбы нет — это задача 6 (скелет и веса к ней готовы).
4. Персонаж не управляется и не взаимодействует — задача 6/7.

### Риски
- Процедурная геометрия «дорогая» по коду, но дешёвая по весу: 0 внешних файлов, ~8.9 тыс. треугольников.
- Ткань/кожа — процедурный атлас 1024². Если понадобится качество выше — заменить на локальные карты, интерфейс `CharacterTextures` это позволяет.

## Задача 3 — Фоновая музыка, подходящая по ситуации

**Статус:** готово к приёмке
**Дата:** 2026-11-24

### Что сделано
- `src/audio/Music.ts` — **собственный музыкальный движок**: живой секвенсор на Web Audio, 16-шаговая сетка, темп/гармония/рисунок для каждого настроения, синтезированные инструменты (пэд, бас, арпеджио-плак, хэт, бочка, снейр, мотив), реверберация со сгенерированным импульсом, лимитер на выходе.
- **Три настроения** (`GOAL.md §7`, задача 3): `menu` (82 BPM, только подложка и тихий бас), `explore` (96 BPM, + бас-рисунок, арпеджио, перкуссия), `mission` (108 BPM, плотнее, своя гармония и мотив).
- **Смена настроения — по событию**, а не по таймеру: `state:changed` (menu / playing / paused), `quest:started` → `mission` + стингер «новая задача», `quest:completed` → `explore` + стингер «успех».
- **Кроссфейд 2–2.5 с** по слоям (`setTargetAtTime`), темп и гармония переключаются на границе такта — без «двойного наложения» и без щелчков (стыков нет по построению: трек не зацикливается, а играется вперёд).
- **Ducking −9 дБ** под реплику героя (`voice:started` / `voice:ended`), плавно 120–350 мс. На паузе музыка приглушается тем же механизмом.
- **Потеря фокуса вкладки** (`visibilitychange`) — музыка замирает и не «догоняет» пропущенное время, при возврате плавно входит.
- **Ползунки** «Музыка» и «Голос» добавлены в настройки (всего 5 громкостей: общая, музыка, голос, эффекты, окружение) — влияют мгновенно.
- Новые события в шине: `quest:started`, `quest:completed`, `voice:started`, `voice:ended`, `music:mood`.

### Проверено (`node tools/check-audio.mjs`)
- `audioReady: true`, движок создан после первого клика (политика автозапуска соблюдена), `isPlaying: true`.
- Настроение: меню → `menu`; игра → `explore`; `quest:started` → `mission`; `quest:completed` → `explore`; возврат в меню → `menu`. Все переходы — по событиям.
- Ducking: `voice:started` → `ducked: true`, `voice:ended` → `false`; пауза → `ducked: true`.
- **Стресс 30 переключений подряд**: планировщик остался один (`timers: 1`), музыка продолжает играть, ошибок нет.
- Реальный сигнал на шине музыки: пик ≈ 0.106 (−19.5 дБFS), RMS ≈ 0.006 — музыка не «пустая» и не клипует (лимитер −14 дБ).
- Ошибок страницы — 0. Скриншот настроек: `shots/audio-01-settings.png`.
- `npm run typecheck` — 0 ошибок; `npm run build` — 862 КБ одним файлом.

### Осталось / известные ограничения
1. **Ambient-слой по зонам** (у моря громче, в доме тише) появится вместе с интерьером (задача 5): сейчас уровень окружения переключается только состоянием.
2. Стингеры написаны, но вызывать их будет контент миссий (задачи 7–8) — сейчас они проверены через события шины.
3. Музыка синтезируется в реальном времени: звук «чиповый», не оркестровый. Если понадобится живой тембр — заменить инструменты движка (структура готова), либо положить локальные сэмплы с лицензией в `ASSETS.md`.

**Статус:** готово к приёмке

- **Плавная нелинейная анимация ходьбы.** `Character.setLocomotion()` + `applyWalk()`: бедро качает ногу с добавкой второй гармоники (`sin φ + 0,14 sin 2φ`), колено подгибается только в переносе, стопа компенсирует наклон, руки качаются в противофазе с ногами и сгибаются в локтях сильнее на бегу, корпус наклоняется вперёд и скручивается, голова стабилизируется, таз покачивается по вертикали и в стороны. ## Задача 11 — Полный экран и мобильное управление

**Статус:** готово к приёмке
**Дата:** 2026-11-26

### Что просили

Добавить в настройки полноэкранный режим и сделать проверку, играет человек на телефоне или на компьютере, — для телефона сделать управление.

### Определение устройства

- `src/core/Platform.ts` — `detectPlatform()` отвечает не по одной строке User-Agent, а по возможностям браузера: `navigator.maxTouchPoints`, `matchMedia('(pointer: coarse)')`, `matchMedia('(hover: none)')`; UA — только подсказка (iPadOS 13+ представляется «Macintosh»). Результат: `touch / phone / tablet / label / reason / fullscreen`.
- Схема управления: `resolveScheme(preference, platform)` — настройка игрока (`auto | keyboard | touch`) важнее автоопределения. Значение живёт в `settings.controls` и сохраняется между запусками.
- Первый запуск на телефоне сразу ставит качество «низкое» (`SettingsStore.firstRun()`): на мобильном GPU дорог каждый пиксель, а поднимать качество можно в настройках.

### Сенсорное управление

- `src/ui/TouchControls.ts` — стик слева (движение; до упора — бег, как Shift), свайп по экрану — обзор, щипок двумя пальцами — приближение камеры, кнопка «Держать» (это ЛКМ: красить стену, замах и бросок мяча), кнопка «Ⓔ» (взаимодействие), «II» — пауза. В режиме покраски появляются «‹», «МАКНУТЬ», «›» для полос и макания валика.
- Виртуальный слой живёт в `Input` (`setVirtualMove/setVirtualLook/setVirtualKey/setVirtualMouse/setVirtualZoom`), поэтому миссии и камера не знают, палец это или мышь — их код не менялся (D-81).
- Захват мыши на телефоне не запрашивается вовсе; выход из pointer lock больше не ставит игру на паузу на мобильных (там захвата нет в принципе).
- Подписи под схему управления: `game.t(keyboard, touch)` — подсказки миссий («Нажми Ⓔ — взять валик», «Держи кнопку и отпусти — бросок»), нижняя подсказка, панель «Управление» (сенсорная раскладка идёт первой). Тексты меню/паузы переключаются классом `.is-touch` на `#ui-root`.
- Раскладка: отступы под «челку» и домашнюю полоску через `env(safe-area-inset-*)`, кнопки диаметром 78–138 px, HUD миссии уводится выше кнопок. В вертикальном положении появляется мягкая подсказка «Поверни телефон».

### Полноэкранный режим

- `src/core/Fullscreen.ts` — обёртка над Fullscreen API с префиксами WebKit, `onChange` и попыткой `screen.orientation.lock('landscape')` на телефоне. Отказ браузера не всплывает исключением: возвращается `false` и показывается уведомление.
- В настройках — переключатель «Полноэкранный режим». Намерение сохраняется (`settings.fullscreen`), но включается только по жесту игрока: браузер не даёт иначе. Если настройка была включена ранее, вход произойдёт по первому нажатию/клавише. Уход из полного экрана (Esc, F11, кнопка браузера) отражается в настройке обратно.

## Задача 14 — Мерцание на домах и «слепые» фасады (26.11)

  переехало вплотную к наличнику (раньше стояло прямо в окне первого этажа).
